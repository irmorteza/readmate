# Translation Languages — Plan B (frontend) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The open word sheet has a language picker. The choice persists, and changing it re-runs the lookup in the new language, with right-to-left targets rendered correctly. Also: the drawer says "Book language: German", and the debug snapshot records the target.

**Architecture:** `languages.ts` wraps the `frontend/src/languages.json` copy that Plan A generated. A `target-language.ts` store (the `dev-mode.ts` pattern) holds the choice. `buildLookup` takes the target. The sheet renders the picker and sets `lang`/`dir` from the answer's target. `result-view.ts` re-runs the lookup for the last selected word when the picker changes, and the existing `lookupId` guard drops late answers.

**Tech Stack:** Vite + TypeScript (no framework), Vitest + jsdom.

**Spec:** `docs/superpowers/specs/2026-10-22-readmate-translation-languages-design.md` §7 (and §4.3 for compatibility).

**Prerequisite:** Plan A is merged and deployed. In particular `frontend/src/languages.json` exists and `isWordInfoResponse` accepts an optional `exampleTranslation` (Plan A Tasks 1–2).

**Execution:** the owner chooses (planned: a separate Sonnet session, after Plan A is deployed).

## Global Constraints

- **BASE:** before Task 1 run `git rev-parse HEAD` and record it. Every "what changed" check compares against BASE, never against `main`.
- Commit locally on `main` after each task. Never push. Run no AWS command. Do not touch `backend/`, `contract/`, `scripts/` or `infra/`.
- Do not edit `frontend/src/languages.json` by hand; it is generated by `scripts/sync_languages.py`.
- `localStorage` key: `readmate.targetLanguage`. The default and fallback is `en`.
- UI copy is exact:
  - picker label "Translate to", `aria-label="Translation language"`;
  - translation card label `"<english> Translation"` for mode `translate` (so English reads "English Translation", today's text) and `"<english> Explanation"` for mode `explain` ("Simple German Explanation");
  - drawer row "Book language: " + **German**;
  - debug panel line `Target: <code> (<english>)`.
- Everything is rendered with `textContent`; no `innerHTML`.
- The debug snapshot format stays `"readmate-debug/2"`.
- Commands from `frontend/`: `npx vitest run`, `npx tsc --noEmit` (use `npx.cmd` if PowerShell blocks `npx`).

## Stop rules

Stop and report instead of continuing when:

- a file outside the task's **Files** list changes (`git diff --stat BASE`);
- an existing test fails that this plan does not name, or a test this plan does not name would need a changed assertion;
- `frontend/src/languages.json` is missing, or `languages.test.ts` fails (Plan A is not in place).

Existing tests this plan **names** as changing:

- `drawer.test.ts` › "shows the target language as static German without a handler" (renamed, new text);
- `debug-snapshot.test.ts` › "describes a word with a sentence" (gains `target: "en"` in `lookup`);
- `result-view.test.ts` › the `mount` helper (gains a fake `targetLanguage` dep, no assertion changes).

## Review Focus

- A stored code that is no longer in the list (a language removed later), or garbage in storage, reads as `en` and the picker shows English (Task 1).
- The user switches language twice quickly: only the answer for the last choice is shown and highlighted (Task 4).
- Changing the picker while no word is selected (the sheet is closing or closed) starts no lookup (Task 4).
- An old backend answers `en` without `exampleTranslation`: the example line shows `exampleEn` with `lang="en"` (Task 3).
- `localStorage.setItem` throws (private mode, quota): the choice still applies for the session and the picker keeps it (Task 1).

### Task 1: Languages module and target-language store

**Files:**
- Create: `frontend/src/languages.ts`, `frontend/src/target-language.ts`
- Test: `frontend/src/languages.test.ts` (extend Plan A's file), `frontend/src/target-language.test.ts`

**Interfaces:**
- Produces, in `languages.ts`:
  - `interface Language { code: string; english: string; native: string; dir: "ltr" | "rtl"; mode: "translate" | "explain" }`
  - `LANGUAGES: readonly Language[]` (file order), `DEFAULT_TARGET: string`
  - `isTargetCode(x: unknown): x is string`, `languageFor(code: string | undefined): Language` (unknown or undefined → the default entry)
- Produces, in `target-language.ts`: `getTargetLanguage(): string`, `setTargetLanguage(code: string): void` (an unknown code is ignored).

- [ ] **Step 1: Write the tests.**
  - `languages.test.ts` adds:
    - `LANGUAGES.map(l => l.code)` equals `["en","de","fa","ar","tr","uk","ru","pl","es","fr","it","zh-Hans"]`;
    - `DEFAULT_TARGET === "en"`;
    - `languageFor("fa")` has `dir: "rtl"`, `native: "فارسی"`;
    - `languageFor("xx")` and `languageFor(undefined)` return the `en` entry;
    - `isTargetCode("FA") === false`.
  - `target-language.test.ts` (`beforeEach` clears `localStorage`, `afterEach` restores mocks):
    - default `en`;
    - `set("fa")` → `get() === "fa"` and `localStorage.getItem("readmate.targetLanguage") === "fa"`;
    - `set("xx")` leaves the previous value;
    - a stored `"klingon"` reads as `en`;
    - when `Storage.prototype.setItem` and `getItem` throw (`vi.spyOn`), `set("ar")` → `get() === "ar"` (memory fallback), and nothing throws.
- [ ] **Step 2: Run** `npx vitest run src/languages.test.ts src/target-language.test.ts`. Expected: fail (modules missing).
- [ ] **Step 3: Implement.**
  - `languages.ts` imports `./languages.json` and casts it to the interface. Literal types are not available from JSON, so `dir` and `mode` are narrowed by the cast; the Plan A sync check guarantees the values.
  - `target-language.ts` mirrors `dev-mode.ts`: a module-level `memory` (initially `DEFAULT_TARGET`); `get` reads storage in a `try` and returns the value only if `isTargetCode`, otherwise `memory` when storage throws, else `DEFAULT_TARGET`; `set` ignores unknown codes, updates `memory`, writes storage in a `try`. No subscribers (YAGNI).
- [ ] **Step 4: Run** `npx vitest run` and `npx tsc --noEmit`. Expected: pass.
- [ ] **Step 5: Commit** `feat(frontend): languages module and persisted target language`.

### Task 3: Word sheet — picker, labels, direction

**Files:**
- Modify: `frontend/src/word-sheet.ts`, `frontend/src/styles.css`
- Test: `frontend/src/word-sheet.test.ts`

**Interfaces:**
- Consumes: `LANGUAGES`, `languageFor` (Task 1); `WordInfo.target`, `WordInfo.exampleTranslation` (Task 2).
- Produces: `WordSheetDeps` gains optional `getTarget?: () => string` (default `() => DEFAULT_TARGET`) and `onTargetChange?: (code: string) => void`. Both are optional, so the existing tests build the sheet unchanged.

- [ ] **Step 1: Write the tests** (new `describe("target language")` in `word-sheet.test.ts`):
  - **Picker.** The sheet contains `select[aria-label="Translation language"]` inside a `.target-picker` row whose text includes "Translate to". The row is placed before `.sheet-header` in document order. The options' `value`s are the codes in `LANGUAGES` order, their `textContent` is `native`, and each option has `lang` = code and `dir` = the entry's `dir`.
  - **Value.** With `getTarget: () => "fa"`, after `showLoading("x")` the select's value is `"fa"`.
  - **Change.** Changing the select to `"ar"` and dispatching `change` calls `onTargetChange("ar")` once.
  - **Labels.** `show({...info, target: "fa"})` → the card label text is "Persian Translation". With `target: "de"` → "Simple German Explanation". Without `target` → "English Translation" (the existing assertion keeps passing).
  - **Direction, `fa`.** `show({...info, target: "fa", translation: "ترجمه", senseInContext: "توضیح", exampleTranslation: "مثال"})`:
    - `.translation`, `.sense` and `.example-en` have `lang="fa" dir="rtl"`, and `.example-en` text is "مثال";
    - `.sheet-word`, `.example-de`, `.lemma-line`, `.noun-line`, the separable infinitive `strong`, both `.parts`, and the expression `strong` have `lang="de" dir="ltr"`;
    - `.phonetic` has `dir="ltr"`.
  - **Expression meaning.** With an expression and `target: "ar"`, `.meaning` has `lang="ar" dir="rtl"`.
  - **Old-backend fallback.** `show({...info, target: "en"})` with no `exampleTranslation` → `.example-en` text is `exampleEn` with `lang="en" dir="ltr"`. `show({...info, target: "fa"})` with no `exampleTranslation` (cannot happen with the new backend, but the guard allows it) → the line shows `exampleEn` with `lang="en"`.
  - **Literal text.** An HTML string in `translation` renders literally (`textContent`).
  - **CSS.** `declarations(".target-select")` contains `min-height: 2.75rem`.
- [ ] **Step 2: Run** `npx vitest run src/word-sheet.test.ts`. Expected: the new tests fail; the existing tests pass.
- [ ] **Step 3: Implement.**
  - **Picker.** A `.target-picker` row (label text "Translate to" plus `select.target-select`) directly after the handle and before the header. `onchange` calls `deps.onTargetChange?.(select.value)`. `showLoading` sets `select.value = getTarget()` and the card label from `languageFor(getTarget())`.
  - **Language of the answer.** In `show(info)`, `const lang = languageFor(info.target)`. Set the label to `` `${lang.english} ${lang.mode === "explain" ? "Explanation" : "Translation"}` ``. Use a helper `setLang(el, code, dir)` for the attributes.
  - **Example line.** It shows `info.exampleTranslation ?? info.exampleEn`. Its language is `lang` when `exampleTranslation` is present, otherwise `languageFor("en")`.
  - **Fixed German and IPA attributes** (`de`/`ltr`, phonetic `dir="ltr"`) are set once at creation.
  - **CSS** for `.target-picker` (flex row, gap, padding matching `.sheet-header`'s `0 1.5rem`, small slate label) and `.target-select` (`min-height: 2.75rem`, `font: inherit`, rounded border using existing tokens). No `text-align: left` exists on these elements, so none needs changing.

- [ ] **Step 1: Write the tests.** In `result-view.test.ts`, the `mount` helper gains a parameter `targetLanguage = fakeTarget()`, where `fakeTarget()` is an in-memory `{ get, set }` starting at `"en"`, and passes it in deps. That is the named helper change. New tests:

  - `it("re-runs the lookup for the current word when the picker changes")`: tap word 2, wait for the answer, change the select to `"ar"` → `set("ar")` was called, `lookup` was called a second time with the same `word`/`wordIndex`/`sentence` and `target: "ar"`, and the sheet shows the second answer.
